# Второй мозг педиатра

Сайт медицинских заметок по подписке для врачей. Часть заметок бесплатна, полная библиотека
открывается по подписке на 1 или 12 месяцев. Девиз: «Быстро. Удобно. Достоверно.»

Стек: Next.js 16 (App Router, TypeScript, Tailwind v4), Prisma 7 + PostgreSQL, NextAuth v5
(email/пароль), оплата подписки — ЮKassa.

## Возможности

- Публичный каталог заметок с поиском, фильтром по тегам и пагинацией; платные материалы
  закрыты paywall'ом.
- Тексты заметок пишутся в markdown (заголовки, списки, таблицы, цитаты); в редакторе админки
  есть переключатель «Редактирование / Просмотр».
- К заметкам прикладываются изображения и PDF: загрузка кнопкой или перетаскиванием прямо
  в текст, файлы хранятся в S3 (Yandex Object Storage) или локально, если S3 не настроен.
- Регистрация/вход по email и паролю, подтверждение email, восстановление пароля.
- Защита от подбора пароля: после 5 неудачных попыток вход по этому адресу блокируется
  на 15 минут.
- Личный кабинет: текущий тариф, история платежей, оформление и отмена автопродления.
- Оплата через ЮKassa (redirect-платежи, сохранение способа оплаты, автоформирование чека
  самозанятого через «Мой налог»).
- Письма: подтверждение адреса, сброс пароля, успешная оплата, напоминание об окончании
  подписки.
- Админка для создания/редактирования/удаления заметок (заголовок, текст, тариф доступа, теги,
  публикация).
- Юридические страницы: публичная оферта, политика обработки персональных данных, FAQ.
- SEO: метаданные страниц, `robots.txt`, `sitemap.xml`.
- Необязательный мониторинг ошибок через Sentry.

## Локальный запуск

1. Установите зависимости:

   ```bash
   npm install
   ```

2. Скопируйте `.env.example` в `.env` и заполните переменные (для локальной разработки БД можно
   поднять в Docker или локальным PostgreSQL):

   ```bash
   cp .env.example .env
   ```

3. Примените миграции и заполните базу демо-данными:

   ```bash
   npx prisma migrate deploy
   npx prisma db seed
   ```

   После сида в консоли будут выведены логин/пароль тестового администратора и врача.

4. Запустите dev-сервер:

   ```bash
   npm run dev
   ```

   Приложение будет доступно на http://localhost:3000.

## Тесты

```bash
npm test        # разовый прогон
npm run test:watch
```

Тесты (vitest) покрывают чистую логику: проверку доступа по тарифам, генерацию слагов,
одноразовые токены и параметры защиты от подбора пароля.

## Переменные окружения

См. `.env.example`:

- `DATABASE_URL` — строка подключения к PostgreSQL.
- `AUTH_SECRET` — секрет NextAuth (сгенерировать: `openssl rand -base64 32`).
- `NEXTAUTH_URL` — публичный URL приложения: ссылки в письмах, `sitemap.xml`, return_url ЮKassa.
- `YOOKASSA_SHOP_ID`, `YOOKASSA_SECRET_KEY` — данные из личного кабинета ЮKassa (Настройки → API).
- `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASSWORD`, `MAIL_FROM` — отправка писем
  (см. [Почта](#почта)). Если не заданы, письма не уходят, а печатаются в консоль сервера —
  удобно для разработки, но на проде их нужно заполнить, иначе пользователи не смогут
  подтвердить email, а без подтверждённого адреса не пройдёт оплата.
- `S3_ENDPOINT`, `S3_REGION`, `S3_BUCKET`, `S3_ACCESS_KEY`, `S3_SECRET_KEY` — хранилище файлов
  заметок. По умолчанию настроено под Yandex Object Storage. Если ключи не заданы, файлы
  пишутся в локальную папку `MEDIA_LOCAL_DIR` (по умолчанию `.media`) — так работает
  разработка без облака; на проде хранилище нужно задать, иначе файлы останутся на диске
  инстанса и пропадут при пересоздании контейнера.
- `CRON_SECRET` — секрет служебного эндпоинта продлений (см. ниже).
- `SENTRY_DSN`, `NEXT_PUBLIC_SENTRY_DSN`, `SENTRY_TRACES_SAMPLE_RATE` — необязательный
  мониторинг ошибок. Без DSN Sentry не инициализируется.

Опционально при сиде: `SEED_ADMIN_EMAIL`, `SEED_ADMIN_PASSWORD`, `SEED_DOCTOR_EMAIL`,
`SEED_DOCTOR_PASSWORD`.

## Почта

Письма уходят с корпоративного ящика `Second_Brain_Pediatra@mail.ru` через SMTP Mail.ru.
Сейчас отправляются четыре транзакционных письма: подтверждение адреса, сброс пароля,
успешная оплата и напоминание за 3 дня до окончания подписки.

### Настройка

1. В почте Mail.ru: **Настройки → Безопасность → Пароли для внешних приложений** — создайте
   пароль. Обычный пароль от аккаунта для SMTP не подойдёт, сервер ответит ошибкой авторизации.
2. Заполните в `.env`:

   ```
   SMTP_HOST="smtp.mail.ru"
   SMTP_PORT="465"
   SMTP_USER="Second_Brain_Pediatra@mail.ru"
   SMTP_PASSWORD="<пароль для внешнего приложения>"
   MAIL_FROM="Second_Brain_Pediatra@mail.ru"
   ```

   `MAIL_FROM` должен совпадать с `SMTP_USER`: письмо от чужого адреса Mail.ru отклонит
   или отправит в спам.

3. Проверьте, не дожидаясь реальной регистрации:

   ```bash
   npm run mail:check                      # только настройки и авторизация
   npm run mail:check -- you@example.com   # плюс тестовое письмо
   ```

### Как это устроено

- Соединение переиспользуется (pool) и ограничено 3 письмами в секунду — почтовые провайдеры
  считают всплески и частые переподключения подозрительными.
- Ошибка отправки **не ломает** регистрацию или оплату, но уходит в Sentry: молча
  отвалившийся SMTP означал бы, что пользователи перестали получать подтверждения,
  а узнали бы мы об этом от них.
- Если письмо всё же не дошло, пользователь может запросить его повторно в личном кабинете.
- У обычного ящика Mail.ru есть суточный лимит на отправку. Для транзакционных писем его
  хватает, но при массовых рассылках по базе понадобится специализированный сервис.

## Ежедневная задача по подпискам

Эндпоинт `POST /api/cron/subscriptions` переводит истёкшие подписки на бесплатный тариф и
рассылает напоминания за 3 дня до окончания. Его нужно вызывать раз в сутки планировщиком:

```bash
curl -X POST https://<ваш-домен>/api/cron/subscriptions \
  -H "Authorization: Bearer $CRON_SECRET"
```

На Vercel это настраивается через `vercel.json` (Cron Jobs), на своём сервере — через
`cron`/systemd timer. Без вызова этой задачи подписка не будет автоматически помечена
истёкшей, а напоминания не уйдут.

## Настройка ЮKassa

1. Зарегистрируйте магазин в [ЮKassa](https://yookassa.ru/) — доступно ИП, юрлицам и
   самозанятым.
2. В личном кабинете включите приём платежей и получите `shopId` и секретный ключ (тестовый — для
   разработки, боевой — для продакшена).
3. В настройках магазина укажите URL вебхука: `https://<ваш-домен>/api/webhooks/yookassa` — на него
   ЮKassa будет присылать уведомления об оплате.
4. Вебхук не доверяет телу запроса напрямую: при получении уведомления сервер перезапрашивает
   статус платежа по API ЮKassa своим секретным ключом и только после этого активирует подписку.
5. Для рекуррентных продлений используется `save_payment_method` — id сохранённого способа оплаты
   пишется в `Subscription.yookassaMethodId`; логику автосписания при продлении (например, через
   cron) нужно добавить отдельно под конкретный процесс биллинга.
6. Для самозанятых: в разделе «Отправка чеков» личного кабинета нужно выдать ЮKassa разрешение
   работать с чеками через «Мой налог». Запрос на создание платежа уже содержит объект `receipt`
   с email покупателя и позицией — без разрешения в кабинете чек не сформируется.

## Структура

- `app/` — страницы (App Router): лендинг, `/notes`, `/pricing`, `/faq`, `/login`, `/register`,
  `/forgot-password`, `/reset-password`, `/account`, `/admin/notes`, `/oferta`, `/privacy`.
- `app/api/` — вебхук ЮKassa, служебная задача по подпискам, роуты NextAuth.
- `lib/actions/` — server actions (регистрация, вход, платежи, подписка, CRUD заметок).
- `lib/yookassa.ts` — интеграция с API ЮKassa, `lib/mail.ts` и `lib/emails.ts` — письма.
- `lib/rate-limit.ts` — защита от подбора пароля, `lib/tokens.ts` — одноразовые токены.
- `prisma/schema.prisma` — модель данных (User, Subscription, Payment, Note, токены, попытки входа).
- `prisma/seed.ts` — демо-данные: админ, врач и заметки в markdown.
- `proxy.ts` — защита маршрутов `/admin` и `/account` (Next.js 16 использует `proxy.ts` вместо
  `middleware.ts`).
- `tests/` — модульные тесты (vitest).
- `deploy/` — готовые Caddyfile и systemd-юниты для боевого сервера.
- `docs/deploy-yandex-cloud.md` — пошаговая инструкция развёртывания.

## Деплой

Подробная инструкция: [`docs/deploy-yandex-cloud.md`](docs/deploy-yandex-cloud.md).

Приложение собирается в режиме `output: "standalone"`, поэтому запускается не через
`next start`, а командой `npm run start` (она поднимает `.next/standalone/server.js`).
Копирование статики и `public/` в каталог standalone выполняет шаг `postbuild`.

Коротко о продакшене:

1. Разверните PostgreSQL и приложение на хостинге **в РФ** — данные граждан России
   должны первично храниться на территории страны (ч. 5 ст. 18 152-ФЗ). Vercel, Supabase
   и Neon по умолчанию этому требованию не отвечают.
2. Задайте переменные окружения, включая SMTP, `CRON_SECRET` и `AUTH_TRUST_HOST=true`
   (без последней NextAuth за обратным прокси отвергает запросы с ошибкой `UntrustedHost`).
3. Выполните `npx prisma migrate deploy`, затем `npm run build`.
4. Замените тестовые ключи ЮKassa на боевые и укажите `NEXTAUTH_URL` с реальным доменом —
   это же значение подставляется в return_url, ссылки из писем и `sitemap.xml`.
5. Настройте ежедневный вызов `/api/cron/subscriptions`.
6. Убедитесь, что сайт работает по HTTPS: через него передаются пароли и персональные данные,
   этого требует ст. 19 152-ФЗ.
7. Не запускайте `prisma db seed` на проде — пароли демо-аккаунтов лежат в репозитории.
   Сид сам откажется работать при `NODE_ENV=production` без собственных
   `SEED_ADMIN_PASSWORD` и `SEED_DOCTOR_PASSWORD`.
